Engineering Realities

The Problem and the Solution

Why software entropy builds up over time, and how autonomous agent loops solve it without taking control away from the engineer.

The Software Entropy Reality

  • ✕
    Invisible Technical Debt: Dead code paths, high cyclomatic complexity, and insecure hashing functions accumulate silently in fast-moving repos.
  • ✕
    Unclear Blast Radiuses: Changing a function without understanding deep call graphs leads to unexpected downstream breaks and regression bugs.
  • ✕
    Fatiguing Review Cycles: Senior developers spend valuable engineering hours triaging simple formatting, missing exceptions, and unused imports.
  • ✕
    Forgotten Developer Preferences: Repeatedly rejecting the same LLM suggestion because generic coding tools have zero memory of your decisions.

The Self-Evolving Approach

  • ✓
    Multi-Tool AST Auditing: Scans using Tree-sitter, Radon, Vulture, and Bandit to locate exact syntax structures and security weaknesses.
  • ✓
    Graph-Aware Impact Analysis: Builds NetworkX module and import graphs to calculate blast radius and avoid breaking dependent callers.
  • ✓
    Self-Healing Test Validation: Automatically executes test suites against candidate fixes, piping traceback errors back to the model for correction.
  • ✓
    Developer Decision Memory: SQLite storage remembers every approved and rejected fix, preventing unwanted suggestions from ever recurring.

Features Built for Real Codebases

AST-Level Codebase Scanning

Combines Tree-sitter AST parsing with Radon (cyclomatic complexity), Vulture (dead functions/variables), and Bandit (security vulnerabilities).

core/scanner.py

Dependency Graph Intelligence

Maps module imports and function caller hierarchies with NetworkX. Visualizes circular dependencies and computes blast radiuses before modifying code.

core/graph.py

Interactive Fix Review Studio

Provides side-by-side diff viewers with syntax coloring, reviewer critiques, test logs, and explicit developer Approve and Reject actions.

ui/static/index.html

Semantic Vector Search

Indexes codebase chunks into ChromaDB vector store. Enables searching logic conceptually in natural language (e.g. "where is token authentication verified").

memory/chroma.py

Developer Decision Memory

Stores approval history, rejection reasons, and verified outcomes in SQLite. The prompt synthesizers query past rejections to avoid repeating mistakes.

memory/sqlite.py

Sandboxed Branch Isolation

Never mutates your current branch directly. Creates isolated agent-fix-* branches with automatic force-rollback if test suites fail.

Local Setup

Get Started in Minutes

Run the entire system locally on your machine with Python 3.11 or 3.12.

Environment:
STEP 1: CLONE REPOSITORY

Clone the repository from GitHub into your local directory.

git clone https://github.com/jayeshtak/Codebase-Self-Evolving-Agent.git cd Codebase-Self-Evolving-Agent
STEP 2: CREATE VIRTUAL ENVIRONMENT

Create an isolated Python 3.12 environment.

python -m venv venv .\venv\Scripts\Activate.ps1 python3 -m venv venv source venv/bin/activate
STEP 3: INSTALL DEPENDENCIES

Install all analysis and multi-agent dependencies from requirements.txt.

pip install -r requirements.txt
STEP 4: CONFIGURE OPTIONAL API KEYS

Copy the environment example. (API keys are optional for offline AST analysis, required for generative LLM loops).

Copy-Item .env.example .env cp .env.example .env
STEP 5: LAUNCH APPLICATION SERVER

Start the FastAPI server on localhost port 8000.

python -m uvicorn ui.server:app --host 127.0.0.1 --port 8000

Then open: http://127.0.0.1:8000/app

System Design

Application Architecture

A cohesive decoupling between user interface, FastAPI server orchestrator, multi-agent core, and persistent memory stores.

Data Flow Summary: The SPA client communicates via REST endpoints with the FastAPI orchestrator. Scans parse syntax trees and dependency graphs to prioritize issues. The Coder agent synthesizes AST patches, which are verified by the Reviewer and Test Executor. Accepted fixes merge to isolated git branches while decisions are indexed into SQLite memory.

Safety First

Security & Developer Governance

Source code is sensitive. Here is how the system guards against accidental breakage and unauthorized changes.

Explicit Human Approval

No code is ever silently committed or merged into your primary branch. Developers must inspect the diff and click Approve.

Isolated Fix Branches

Every candidate fix is committed to an isolated agent-fix-* branch. If validation fails, Git immediately rolls back to clean HEAD.

Sandbox & Demo Isolation

Setting DEMO_MODE=true prevents filesystem escape and disallows unauthorized branch checkout, making live demonstrations completely safe.
